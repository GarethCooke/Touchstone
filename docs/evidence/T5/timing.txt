T5 · timing evidence — the five entry points at their defaults
================================================================

Taken 2026-11-14, between 01:20:50 and 01:21:46 UTC, on one machine, with one compiler at
one setting of its flags. Nothing here claims a time on any other machine, compiler or flag,
for the WebAssembly build (not timed), or for any input but the one in section 1.

1. What was timed
-----------------

  The harness is bench/timing.cpp, committed on this branch and built by
  bench/CMakeLists.txt wherever the tests are built. It uses the C++ standard library and
  the library, nothing else (I19).

  One option and one market, the base case of every figure below:

    call, K = 100, T = 1; S = 100, sigma = 0.2, r = 0.05, q = 0.02

  The five entry points, each with every setting at its default:

    price_and_greeks(option, market)
    implied_vol(option, QuotedMarket::of(market), target)  target = price(option, market);
                                                           ImpliedVolSettings{}
    bump_greeks(option, market)                            the closed-form overload;
                                                           BumpSizes{}
    monte_carlo(option, market)                            MonteCarloSettings{}: seed 1,
                                                           32768 paths, exact, no antithetics
    crank_nicolson(option, market)                         PdeSettings{}: 1024 x 512,
                                                           half-width 6, 2 Rannacher steps,
                                                           cell-averaged payoff

  What each returned is printed at the top of each run (section 6), so the output says what
  was computed as well as how long it took. The Monte Carlo price, 9.2654458141056377, is
  the price docs/evidence/T3a/timing.txt printed for the same option, market and settings.

2. How
------

  A call to price_and_greeks takes less time than a clock read resolves, so calls are timed
  in batches. For each entry point the harness doubles a batch, from one call, until a batch
  takes at least 20 ms by std::chrono::steady_clock; that count is the entry point's batch
  size for the run. Three warm-up batches follow. A round then times five batches of each
  entry point and keeps, per entry point, the median of the five divided by the batch size.
  The order of the five rotates by one each round. After 25 rounds the summary gives, per
  entry point, the median round and the lowest and highest.

  The batch loop is a template instantiated around each entry point's call, so the call is
  direct; the harness's one indirection, a std::function, is taken once per batch. After
  every call the harness reads and writes a volatile double so that no result is unused:
  one load and one store per call, which the times include.

  Three processes were run one after another, each pinned to logical processor 3 at high
  priority, from PowerShell 7:

    $exe = "<build>\bench\touchstone_timing.exe"
    foreach ($run in 1..3) {
        $p = Start-Process -FilePath $exe -ArgumentList 25 -NoNewWindow -PassThru `
                           -RedirectStandardOutput "timing-run$run.txt"
        $p.ProcessorAffinity = [IntPtr](1 -shl 3)
        $p.PriorityClass = 'High'
        $p.WaitForExit()
    }

  The affinity and priority are set as soon as Start-Process returns, so the harness's
  first calibration batches may run before the pin takes effect; the timed rounds come after
  calibration and three warm-up batches per entry point, and are pinned. No build or test was
  running at the time; the desktop session was otherwise in ordinary use.

5. What it says, on this machine
--------------------------------

  - The three runs' medians agree: for every entry point the largest is within
    3.7% of the smallest.
  - The slowest round of any entry point in any run is 1.33 times its run's median
    (price_and_greeks, run 1: 100.7 ns against 75.9 ns). What made the
    slow rounds slow was not measured; a median of 25 rounds does not rest on a few of them.
  - crank_nicolson at its defaults took 4.7 ms here. pde.hpp said "about eight
    milliseconds", with no recorded measurement (F4); that sentence is cut, and the header
    points to ARCHITECTURE.md instead.
  - Nothing here is compared with ruling 7's rough first timings
    (docs/briefs/T3a-design-rulings.md: another machine, g++ 13.3) or with
    docs/evidence/T3a/timing.txt (this machine, one function, another method).

  Not measured: the WebAssembly build; any other input; any setting but the defaults; Clang;
  MSVC; any other machine. Nothing in the library was changed to be timed.
