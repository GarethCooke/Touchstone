fail, so the margin is on the record rather than inferred from a green tick.

max(|reference|, 1.0) — relative above 1.0, absolute below it, because a

  The roadmap's figure for T1 is 1e-10, and the golden file carries it, so the
  tests read it rather than restate it.

  The narrowest margin is rho and dividend_rho at a few times 1e-13, which is
  where it belongs: both carry a factor of T, so a five-year row multiplies the
  price-level error by five before the comparison is made.

  The edge block's worst is theta at 1.6e-11 on a one-day option. SCHEMA.md
  predicts exactly this and says not to chase it: QuantLib derives theta by a
  route that divides by the year fraction, so the reference itself is only good
  to about 1e-11 absolute at one day. The closed form here is the more accurate
  of the two, and the gap is the oracle's.

4. What the four suites would catch
-----------------------------------

  normal       N(x) or phi(x) wrong, including the left tail. N(-10) is 7.6e-24;
               an implementation computing it as 1 - N(10) returns exactly zero,
               and the suite demonstrates that collapse rather than asserting it.
               Tolerances are (4 + x^2) * eps, which is the conditioning of the
               problem — the rounding of x itself is amplified by |d ln N/dx|,
               and that grows like |x| in the tail — not a number chosen to pass.

  closed-form  Any of the seven values disagreeing with QuantLib on any of 7234
               rows. Also: the golden file silently becoming a different file
               (its schema id is checked), and the seven single-value accessors
               drifting from price_and_greeks (worst difference over 7200 rows x
               7 values: exactly zero).

  parity       Put-call parity or one of the six identities the Greeks inherit
               from it. This suite reads the golden file for its parameter sweep
               and for nothing else: every number compared is one this library
               produced, so it would fail even if the oracle were wrong about
               every row. Tolerance 1e-13, three orders tighter than the golden
               sweep, because these are exact algebraic identities; not tighter
               still because the identity is a difference of two numbers of order
               S, and one ulp of the grid's largest spot is 2.8e-14.

  limits       The closed form failing to reduce to a forward contract as
               volatility goes to zero, or to its payoff as expiry does;
               diverging where it should not; returning a number where the limit
               is infinite; or producing a NaN anywhere in the domain
               require_valid accepts. The last of those is a 25,920-point sweep
               of the domain's boundary, including spots and strikes of 1e-300
               and 1e300, vols of 1e-300 and 1e100, and expiries of 1e-300 and
               1e300: 16,570 priced with no NaN in any of seven outputs, 9,350
               rejected with a specific message, 550 with the infinite gamma the
               mathematics has at the strike.

8. Putting each defect back
---------------------------

A fix with no failing test behind it is a change, not a repair. Each of the four
code fixes the adversarial review prompted was reverted in a scratch copy on host
B, and the limits suite re-run against it. Baseline for that suite: 11 cases,
251,909 assertions, all passing.

  reverted fix                                   assertions failed
  ------------------------------------------------------------------
  at-the-forward decided on S e^-qT - K e^-rT              2
  decay branch reading "sigma != 0" as "T == 0"            2
  gamma forming S*v and dividing by the product         1042
  representability checks removed from require_valid    1026

A fifth change — moving the "nothing against nothing" guard above the arithmetic
— has no such number, and should not be claimed to. Once require_valid rejects an
overflowing discount factor, K * exp(-rT) can no longer be 0 * inf, so the
poisoned kernel that motivated the reordering is unreachable. The guard stays
because it is free and because it makes the comment beside it true, not because a
test would notice its absence.
