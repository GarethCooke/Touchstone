T3a · timing evidence — Monte Carlo, main against the branch, before and after the fix
====================================================================================

Taken 2026-11-12 on one machine, for one compiler, at one setting of its flags. Nothing here
claims a time on any other machine, compiler or flag, and nothing claims a time for any
function but monte_carlo at the two settings below.

1. What was timed, and how
--------------------------

  Compiler    g++ 15.2.0 (x86_64-posix-seh-rev0, MinGW-Builds), libstdc++, the MinGW runtime
  Library     CMAKE_BUILD_TYPE=Release, which for g++ is -O3 -DNDEBUG; -std=c++20 and the
              project's warning flags; TOUCHSTONE_BUILD_TESTS=OFF; a static library
  Harness     g++ -O3 -DNDEBUG -std=c++20, linked against each library (source in section 5)

  Four libraries, each built the same way:

    main      6b8a60a
    before    c4eb343, the branch as it was pushed
    after     this change
    attrib.   this change with one line altered and never committed: detail::advance as the
              plain product `current * factor`, without its two zero tests. It exists only to
              say how much of what remains is those tests.

  The call: monte_carlo on a call, K = 100, T = 1; S = 100, sigma = 0.2, r = 0.05, q = 0.02.
  Two settings:

    default   MonteCarloSettings{} — exact scheme, 32768 paths, seed 1, no antithetic
    euler64   the same with scheme = EulerMaruyama, steps = 64 (2,097,152 path-steps)

  Each process makes 3 warm-up calls per setting, then 40 timed Euler calls and 400 timed
  default calls, and prints the median wall time of one call (std::chrono::steady_clock).
  A driver (section 6) runs the four executables in turn for 15 rounds, the order rotated by
  one each round, each process pinned to one logical core at high priority. The figure
  reported is the median of the 15 medians, with the smallest and largest beside it.

  Every executable printed the same price for each setting, to 17 significant digits:
  9.2221528015480025 (euler64) and 9.2654458141056377 (default).

3. What it says, on this machine
--------------------------------

  - At the default settings the change takes monte_carlo from 1.756 ms back to 1.718 ms,
    against main's 1.712 — a difference from main smaller than the spread of main's own runs.

  - Under Euler at 64 steps it takes the call from 35.8 ms to 31.5 ms: 59% of the 7.2 ms the
    branch had lost against main. 2.9 ms (10%) remains.

  - About half of that remainder, 1.5 ms, is detail::advance's two zero tests, which main's
    Monte Carlo loop did not make: without them (the attribution build) the call is 30.0 ms.
    The other 1.5 ms was not attributed.

  - The zero tests stay. They are what makes an infinity times a zero impossible in a path,
    which is why the path API cannot return a NaN. A formulation returning the same bits in
    every case with one test on the product in place of two on the operands —

        const double product = current * factor;
        if (std::fabs(product) > 0.0) return product;
        return (current == 0.0 || factor == 0.0) ? 0.0 : product;

    — was built and timed in an earlier run of the same driver and measured no faster
    (section 4), so the rule is kept as written.

  It does not say how the branch compares with main on CI's g++ 13.3, on clang, on MSVC, at
  other flags or on other hardware. The timing this follows (g++ 13.3, -O3, another
  machine: euler64 20.6 -> 28.5 ms, default 1.17 -> 1.29 ms) was not reproduced here, and
  its percentages differ from these.

  Moving draw into the header (after-1 -> exp4) is what brought the default setting back:
  under the exact scheme a path is one normal, so draw was a call across translation units
  once per path, as the factor was once per step. The one-test advance (exp2) did nothing
  measurable at either setting.

  g++'s -O3 assembly for monte_carlo.cpp after the change has the scheme's test outside the
  walk's loop: one loop per scheme, chosen once at entry, with the factor inlined. No
  compile-time dispatch on the scheme was added, because the compiler already does this
  once it can see the factor.

5. The harness, verbatim
------------------------

    // Times one call of touchstone::monte_carlo, for two settings: the defaults
    // (exact scheme, 32768 paths) and Euler-Maruyama at 64 steps over the same
    // paths. Compiled once against each library under comparison; the source uses
    // only what main and the branch share.
    //
    //   timing <label> <euler calls> <default calls>
    //
    // Prints one line per setting: label, setting, the median wall time of one
    // call in milliseconds over the calls made, and the price as a check that the
    // libraries compute the same thing.

    #include <touchstone/monte_carlo.hpp>

    #include <algorithm>
    #include <chrono>
    #include <cstdio>
    #include <cstdlib>
    #include <vector>

    namespace {

    volatile double sink = 0.0;

    double median_ms(const touchstone::EuropeanVanilla& option,
                     const touchstone::BlackScholesMarket& market,
                     const touchstone::MonteCarloSettings& settings,
                     int calls,
                     double& price)
    {
        for (int i = 0; i < 3; ++i) {
            sink = sink + touchstone::monte_carlo(option, market, settings).price;
        }
        std::vector<double> ms;
        ms.reserve(static_cast<std::size_t>(calls));
        for (int i = 0; i < calls; ++i) {
            const auto start = std::chrono::steady_clock::now();
            const touchstone::MonteCarloResult result = touchstone::monte_carlo(option, market, settings);
            const auto stop = std::chrono::steady_clock::now();
            price = result.price;
            sink = sink + result.price;
            ms.push_back(std::chrono::duration<double, std::milli>(stop - start).count());
        }
        std::sort(ms.begin(), ms.end());
        return ms[ms.size() / 2];
    }

    }  // namespace

    int main(int argc, char** argv)
    {
        if (argc != 4) {
            std::fprintf(stderr, "usage: timing <label> <euler calls> <default calls>\n");
            return 2;
        }
        const char* label = argv[1];
        const int euler_calls = std::atoi(argv[2]);
        const int default_calls = std::atoi(argv[3]);

        touchstone::EuropeanVanilla option{};
        option.strike = 100.0;
        option.expiry_years = 1.0;
        option.type = touchstone::OptionType::Call;

        touchstone::BlackScholesMarket market{};
        market.spot = 100.0;
        market.vol = 0.2;
        market.rate = 0.05;
        market.dividend_yield = 0.02;

        const touchstone::MonteCarloSettings defaults{};

        touchstone::MonteCarloSettings euler{};
        euler.scheme = touchstone::Scheme::EulerMaruyama;
        euler.steps = 64;

        double price = 0.0;
        const double euler_ms = median_ms(option, market, euler, euler_calls, price);
        std::printf("%s euler64 %.4f %.17g\n", label, euler_ms, price);
        const double default_ms = median_ms(option, market, defaults, default_calls, price);
        std::printf("%s default %.4f %.17g\n", label, default_ms, price);
        return 0;
    }

6. The driver, verbatim (PowerShell 7)
--------------------------------------

    # Runs each timing executable in turn, round after round, the order rotated each
    # round, every process pinned to one core at high priority. Prints the raw lines
    # and then, per variant and setting, the median over rounds of each run's median.
    param(
        [string[]]$Variants,
        [int]$Rounds = 11,
        [int]$EulerCalls = 30,
        [int]$DefaultCalls = 300,
        [int]$Core = 3,
        [string]$Dir = $PSScriptRoot
    )

    $raw = @()
    for ($round = 0; $round -lt $Rounds; $round++) {
        $order = @()
        for ($i = 0; $i -lt $Variants.Count; $i++) {
            $order += $Variants[($i + $round) % $Variants.Count]
        }
        foreach ($v in $order) {
            $out = Join-Path $env:TEMP "timing-$v.out"
            $p = Start-Process -FilePath (Join-Path $Dir "timing-$v.exe") `
                -ArgumentList $v, $EulerCalls, $DefaultCalls `
                -NoNewWindow -PassThru -RedirectStandardOutput $out
            try {
                $p.ProcessorAffinity = [IntPtr](1 -shl $Core)
                $p.PriorityClass = 'High'
            } catch {}
            $p.WaitForExit()
            $raw += Get-Content $out
        }
    }

    $raw | ForEach-Object { "raw $_" }

    $rows = $raw | ForEach-Object {
        $f = $_ -split ' '
        [pscustomobject]@{ Variant = $f[0]; Setting = $f[1]; Ms = [double]$f[2]; Price = $f[3] }
    }
    foreach ($setting in 'euler64', 'default') {
        foreach ($v in $Variants) {
            $ms = @($rows | Where-Object { $_.Variant -eq $v -and $_.Setting -eq $setting } |
                    ForEach-Object { $_.Ms } | Sort-Object)
            $prices = @($rows | Where-Object { $_.Variant -eq $v -and $_.Setting -eq $setting } |
                        ForEach-Object { $_.Price } | Sort-Object -Unique)
            $median = $ms[[int][Math]::Floor($ms.Count / 2)]
            "{0,-8} {1,-8} median {2,8:F3} ms   min {3,8:F3}   max {4,8:F3}   runs {5}   price {6}" -f `
                $setting, $v, $median, $ms[0], $ms[-1], $ms.Count, ($prices -join ',')
        }
    }

  Run as:  drive.ps1 -Variants main,before,after,exp -Rounds 15 -EulerCalls 40 -DefaultCalls 400
