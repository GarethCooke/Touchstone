2. Behaviour preserved: the suite's own numbers, before and after
----------------------------------------------------------------

  The test binary prints every number it asserts on: worst errors, convergence ratios,
  standard-error tables, counts. Both builds of main were run first and their whole output
  kept. The branch's output was then compared with it line by line, after removing file
  paths and line numbers, which moved.

  g++ 15.2, main against branch, lines that differ (new tests' output aside):

    test_american.cpp, "where early exercise is worthless, the grid says so exactly":
      worst |american grid - european grid|    2.492e-13  ->  2.784e-13    (bound 1e-11)
    test_tridiagonal.cpp, projected sweep against projected SOR, lower region:
      worst |sweep - PSOR|                     3.109e-15  ->  2.665e-15    (bound 1e-9)

  clang 22, main against branch: the same two lines, the same numbers.

  g++ 15.2 branch against clang 22 branch: no line differs.

  Why those two and no others. The plain Thomas solve and the two directions of the
  projected one are now one sweep (R7), and that sweep keeps the plain solve's arithmetic —
  the eliminated superdiagonal, divided as it goes — so every European solve, and through
  them every finite-difference, three-way and bump-on-grid number, is bit-identical. The
  projected solves previously kept the pivots and divided at substitution: the same
  algorithm, factored differently, so they now round differently. Both numbers above are
  measures of round-off between two factorisations of one matrix, and both stay orders
  inside their bounds. The comment in test_american.cpp already said why the American and
  European grids agree "to round-off rather than exactly" for a put and exactly for a call,
  and that is still what they do.

  Everything else that moved in the library — the closed form behind one class, the
  implied-vol solvers on its volatility-free half, Monte Carlo on the path generator, the
  bump list, the grid's matrices built once — reproduces the old numbers to the last digit
  printed. Newton-Brent's seed now reads the forward log-moneyness as the closed form forms
  it; its reported worst residual, iteration counts and method counts did not move:

    price round trip over 7234 rows: worst scaled |repriced - golden| 1.476e-12;
      Newton 6910, Brent 0, exact at zero 324, not converged 0; worst iteration count 27
    with one Newton step allowed: 982 of 1029 rows finished in Brent; worst 1.07e-12

6. What each new suite would catch
----------------------------------

  ts_paths                  a path API that draws a different stream, steps a different
                            scheme, clips Euler, or saturates to a NaN
  ts_implied-vol-safeguarded a solver that takes a different step from page 2.11's, counts
                            its bisections differently, words a status differently, or
                            loses a golden price
  ts_contract               an American contract reaching the closed form, Monte Carlo,
                            implied vol or bump Greeks — by failing to compile
  additions to ts_pde       a grid solver whose stepped surface is not crank_nicolson's, or
                            whose solution is wrong away from the spot node
  additions to ts_closed-form a quote and a one-shot evaluation that compute differently, or
                            two halves that between them guard a different domain

9. The Monte Carlo timing follow-up
-----------------------------------

  After an independent timing showed Monte Carlo slower on the branch than on main, the Euler
  path's two walks became one walk carrying both values, and GbmStep and
  PathGenerator::draw moved into their header (summary.md, the entry of the same date;
  timing.txt). The suite was re-run on both local compilers, from the same build directories
  as section 7, and its output compared with section 7's runs, paths and line numbers removed
  as in section 2:

  Where                          Cases   Assertions   Result
  g++ 15.2, -Werror              116     4,140,435    all passed; 0 warnings; output
                                                      identical to section 7's, 688 lines
  clang 22                       116     4,140,435    all passed; 0 warnings outside tests/;
                                                      output identical to section 7's byte
                                                      for byte, paths and line numbers
                                                      included
  g++ against clang                                   identical line for line

  g++'s raw output differs from its section 7 run only in five line numbers of
  test_monte_carlo.cpp, each one greater: that run was taken before 47c8108 added
  #include <utility> to the file, and the clang run after. Every number the suite prints is
  unchanged on both compilers.

  Why nothing moved: the factor is the same expression, formed once a step for both carried
  values rather than once a step in each of two walks, and each carried value is multiplied
  by it in the order main's loop multiplied them, growth first, then the discounted growth.
  The exact scheme's path is unchanged: one step from one, then one multiplication by the
  discount, with the exponential recovery where that is not finite.
