  (b) Every assertion's values. The -s output before and after was normalised as T5 did
      (line numbers removed, pointer addresses masked), then compared as multisets of lines.
      For each line of the before run, the question is whether it occurs fewer times after.
      A line-by-line diff does not work here: once assertions are inserted mid-stream, GNU
      diff's heuristic misaligns the 14 million lines and reports 1.4 million changed lines,
      all of which are present unchanged on both sides.

      g++: 17 distinct lines occur fewer times after. Every one is in test_normal.cpp or is
      a count.
        - 9 lines are the reference checks' expression text. It changed when the references
          moved to golden/normal-known-answers.json (the review's R4).
        - 2 lines are doctest's totals (120 cases, 4,140,490 assertions).
        - "CHECK( 1935 > 0 )" is the saturation count in "an accepted path never holds a
          NaN". It is now 9,586, because every extreme is also stepped as a sample.
        - "CHECK( 0.5 == 0.5 )" is N(0). It is now a fixture row with a tolerance of zero,
          printed "CHECK( 0 <= 0 )".
        - 4 lines are relative errors of N(x) against its references, and those errors
          moved: "CHECK( 0 <= 1.11e-15 )" at x = 1 is now "CHECK( 1.32e-16 <= 1.11e-15 )".
          The references are not the cause: nlohmann/json, strtod and the C++ literal parse
          all seven to identical doubles, and normal.hpp did not change. The argument is.
          The old test called norm_cdf(1.0) on a literal, and g++ folds that call at compile
          time with MPFR, correctly rounded:
            literal N(1)  0x1.aec4bd120d37dp-1   (the reference exactly)
            runtime N(1)  0x1.aec4bd120d37ep-1   (MinGW's erfc, one ulp off)
          Read from the fixture, x is a runtime value. So the test now measures the runtime
          function, which is what the library's callers and the module get. Each error is
          still inside its tolerance; the largest is 3.86e-15 against 2.31e-14 at x = -10.
          Clang does not fold erfc, and on Clang these four lines do not move.

      clang++: the same 13 lines as g++, less the four above, plus 97 lines of binary data
      that come from the before run's output file. About 80 lines of bytes sit where a
      test_rng.cpp line should be, near line 7,213,589 of 14.4 million. That file was written
      while other builds ran. The run itself passed all 120 cases, the after run's file has no
      such lines, and neither g++ file has any. So for Clang the comparison holds everywhere
      except that one patch of test_rng.cpp, and the g++ comparison covers that patch.

      Every other line of the before runs (number, expression and message) occurs at least
      as often after, on both compilers.

  (c) The module. Two checks against v1.0.0's artifact, built here at fbf90f9.

      First, v1.0.0's own wasm/smoke.test.mjs, run against this branch's artifact: 16 of 17

      more key, impliedVolNewtonBrent, which is the change ruling 10 approved. Its five other
      keys are unchanged.

      Second, a differential. Every v1.0.0 export was called with the same arguments on both

        - every 37th row through monteCarlo (two settings), crankNicolson (European and
          American), crankNicolsonSurface and bumpGreeks (three pricers);
        - 200 seeds through uniforms, normals, brownianPath and gbmPath (both schemes);
        - thirteen refusals and wrong shapes.

        DIFFERS defaults []
