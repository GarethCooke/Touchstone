T4 · build evidence
===================

Branch m/T4. Base 1a9b465 (main: "ticked milestone: T3a — Settle the library before it is
bound"). Local builds on one machine; CI (tests.txt section 4) is the authoritative run.

1. The machine and the toolchains
---------------------------------

  Machine     AMD Ryzen 7 3800X 8-Core, Windows 11 Pro 10.0.26200
  Emscripten  6.0.13 (e13ee988), from emscripten-core/emsdk tag 6.0.13, installed at
              C:\local\emsdk; its clang is 24.0.0git (83ee0779)
  Node        v24.13.1 locally; CI runs the smoke test on Node 22, the site's (I19)
  CMake       3.31.6 (Visual Studio 2022's), Ninja 1.12.1
  g++         15.2.0 (MinGW-Builds), for the native suite only (section 4)

  Why 6.0.13. The newest emsdk tag on the day was 7.0.0, published 2026-11-06, one week
  earlier; 6.0.13 was published 2026-10-19. The session's rule is a version at least two
  weeks old. CI installs the same tag from the same first-party repository
  (.github/workflows/wasm.yml, EMSDK_VERSION), so the local build and CI's are one toolchain.

2. How the artifact is built
----------------------------

    source <emsdk>/emsdk_env.sh
    wasm/build.sh                 # CMAKE_GENERATOR=Ninja on Windows

  which runs, for each of the two builds,

    emcmake cmake -S . -B build-wasm[-noexcept] -DCMAKE_BUILD_TYPE=Release \
                  -DTOUCHSTONE_WASM_EXCEPTIONS=ON|OFF
    cmake --build build-wasm[-noexcept]

  Release is -O3 -DNDEBUG. TOUCHSTONE_WASM_EXCEPTIONS=ON adds -fwasm-exceptions to every
  translation unit and to the link, the library's included (CMakeLists.txt). The link
  options are in wasm/CMakeLists.txt: -lembind, MODULARIZE + EXPORT_ES6 (an ES module
  exporting createTouchstone), ENVIRONMENT=web,worker,node, ALLOW_MEMORY_GROWTH,
  FILESYSTEM=0, and --post-js=wasm/errors.post.js. Under Emscripten the native test suite is
  not configured (TOUCHSTONE_BUILD_TESTS defaults OFF there); the header self-containment
  check is, and builds.

  Warnings. Every translation unit, the binding included, is compiled with the project's
  warning set and -Werror (touchstone_warnings). Both builds: 0 warnings.

  The library's sources are unchanged. This is the first time Emscripten has built them
  (F7's Emscripten half), and they built as they are.

3. Size
-------

  wasm/build.sh's report on the final tree (build-wasm/size.txt), bytes:

                               .wasm      .mjs     total gzip -9 total
    catching on (shipped)     145104     28786    173890         56017
    catching off              112851     29389    142240         50024

    budget                                        500000

  The budget is read strictly: the .wasm and the .mjs together, uncompressed, against
  500,000 bytes (500 KB at 1000 bytes to the KB). The shipped artifact is 34.8% of it.
  wasm/build.sh fails the build above it, which fails CI and the release.

  What catching costs: 31,650 bytes (+22%) uncompressed, 5,993 bytes gzipped.

  For comparison only, not shipped: Emscripten's JavaScript-based exception handling
  (-fexceptions in place of -fwasm-exceptions, built in build-wasm-jseh by hand):

    catching on, JS-based EH  187091     34264    221355         60405

  It passes the same smoke test (17 of 17). It costs 79,115 bytes against the 31,650 of
  WebAssembly's own exception handling, which is why the latter ships (summary.md,
  Decisions).

4. The native build, unchanged
------------------------------

  The root CMakeLists.txt gained the version (0.1.0 -> 0.4.0), an Emscripten-only block and
  an Emscripten-only add_subdirectory(wasm). The native configuration takes none of them.

    cmake -S . -B build-gcc-t4 -G Ninja -DCMAKE_CXX_COMPILER=g++ -DCMAKE_BUILD_TYPE=RelWithDebInfo
    cmake --build build-gcc-t4          # 0 warnings, -Werror on

  The suite's result is in tests.txt section 3; CI's three native jobs in section 4.

  Note on this machine: from the session's Bash shell, MinGW g++'s cc1plus exited 1 with no
  message, even on an empty main(); from PowerShell the same g++ compiled it. The native
  build was therefore run from PowerShell. Nothing in the repository is involved.
