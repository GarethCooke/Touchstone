# experiments

One script per tutorial section. Each writes a JSON result committed beside it.

This is Crucible's discipline, adopted here by tech-decision A9 and required by the
constitution's §7: an experiment is not a notebook you ran once and screenshotted, it is a
file that runs, a result you can diff, and a claim someone else can re-derive.

## The discipline

**One script, one JSON, one commit.** `2_3_quadratic_variation.py` writes
`2_3_quadratic_variation.json` beside it. Both are committed. A script whose result is not
committed has not finished; a JSON whose script is not committed is not evidence.

**Name for the page it serves.** `<part>_<section>_<slug>.py`, matching the page id in
`docs/quant-learn-index-v1.md` — `2_1_random_walks.py` for page 2.1. A script that serves no
page needs a reason in its docstring.

**Seed everything** (I6). Every script that draws random numbers takes an explicit seed and
records it in its JSON. Same seed, same result, on any machine. `numpy.random.default_rng(seed)`
— never the legacy global functions, never an unseeded default.

**Record the inputs in the output.** The JSON carries the parameters that produced it, not
just the numbers that came out. A result you cannot regenerate from its own file is a
screenshot with extra steps.

**Print nothing that matters.** Anything a page quotes goes in the JSON. Standard output is
for progress, not for results — the tutorial reads the file.

**No plotting here.** These scripts produce numbers; the site draws them (I15, and the demo
registry). A script that needs a picture to make its point is telling you the demo is
missing.

## What the results are for

Three consumers, which is why the discipline is stricter than a scratch script deserves:

1. **Tutorial snippets.** Every snippet shown on a page is extracted from a file that runs in
   CI (I3). These are those files. Prose-only code is forbidden.
2. **Demo fixtures.** The site's demos check themselves against committed results rather than
   against numbers typed into a test.
3. **The library's tests.** Where an experiment establishes a property the C++ must also have,
   its JSON becomes a test input.

## What does not live here

`golden/` — the QuantLib oracle. It is reference data for the library's tests rather than an
experiment behind a page, it is generated by a different tool, and it carries its own schema
and tolerances. See [`../golden/SCHEMA.md`](../golden/SCHEMA.md).

## Running

The `uv` project is rooted at the repository root, not here.

```bash
uv sync
uv run experiments/2_1_random_walks.py
```
